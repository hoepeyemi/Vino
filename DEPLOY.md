Distribution ID: `EW5RCZ2SGZCCM`  
Domain: `dkwc0vn4y827h.cloudfront.net`

### Origins

| Name | Domain | Port | Protocol |
|---|---|---|---|
| `vino-app` | `ec2-54-91-79-0.compute-1.amazonaws.com` | 3000 | HTTP only |
| `vino-agent` | `ec2-54-91-79-0.compute-1.amazonaws.com` | 8080 | HTTP only |

### Behaviors (in precedence order)

| Precedence | Path | Origin | Cache Policy | Origin Request Policy |
|---|---|---|---|---|
| 0 | `/ws*` | `vino-agent` (**:8080**) | **CachingDisabled** | Managed-AllViewer |
| 1 (default) | `/*` | `vino-app` (**:3000**) | Managed-CachingDisabled | Managed-AllViewer |

**Critical**: The `/ws*` behavior **must** use `CachingDisabled` (not `UseOriginCacheControlHeaders`) — any caching policy breaks the WebSocket upgrade handshake. The origin must specify `:8080` explicitly.

### EC2 Security Group

Inbound rules required:

| Port | Protocol | Source | Purpose |
|---|---|---|---|
| 22 | TCP | Your IP | SSH |
| 3000 | TCP | 0.0.0.0/0 | Next.js (CloudFront → EC2) |
| 8080 | TCP | 0.0.0.0/0 | Agent WebSocket (CloudFront → EC2) |

## GitHub Secrets Required

Set these once in **Settings → Secrets and variables → Actions**:

| Secret | Description |
|---|---|
| `DOCKER_USERNAME` | Docker Hub username |
| `DOCKER_PASSWORD` | Docker Hub password or access token |
| `SSH_HOST` | Server IP (`54.91.79.0`) or hostname |
| `SSH_USERNAME` | SSH login user |
| `SSH_PRIVATE_KEY` | Ed25519 private key for SSH access (generated by `server-setup.sh`) |

No contract addresses, RPC URLs, or `NEXT_PUBLIC_*` values belong in GitHub secrets — they are either baked into the Docker image at build time or live in `~/vino/.env.app` / `~/vino/.env.agent` on the server.

## Server Setup (one-time)

SSH into the server and run the setup script:

```bash
bash scripts/server-setup.sh
```

Or remotely:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/hoepeyemi/Vino/main/scripts/server-setup.sh)
```

The script:
1. Installs Docker (official repo) if not present
2. Adds the current user to the `docker` group
3. Creates `~/vino/agent-data/`
4. Writes `~/vino/.env.app` and `~/vino/.env.agent` stubs with contract addresses pre-filled
5. Generates an Ed25519 SSH deploy key at `~/.ssh/vino_deploy`
6. Adds the key to `authorized_keys`
7. Configures UFW (opens ports 22, 3000, 8080)
8. Prints the 5 GitHub secrets you need to add

> **After running the script**, log out and back in so the `docker` group takes effect, then fill in the blank values in `~/vino/.env.app` and `~/vino/.env.agent`.

## How CI/CD Works

On every push to `main`, the pipeline (`.github/workflows/ci.yml`) runs three jobs:

### Job 1 — Test
- Typechecks agent (`pnpm tsc --noEmit`)
- Runs agent test suite (`pnpm test`)
- Runs agent build smoke test (`pnpm build`)
- Typechecks app (`tsc --noEmit`)
- Lints app (`eslint src/ --max-warnings 0`)

### Job 2 — Build & Push
- Builds `Dockerfile.web` → pushes as `<user>/vino-app:latest`
- Builds `Dockerfile.mcp` → pushes as `<user>/vino-agent:latest`
- Contract addresses and RPC URLs are **baked in at build time** (not secrets)
- Three `NEXT_PUBLIC_*` vars use placeholder strings replaced at container startup:
  - `__VINO_AGENT_WS_URL__` → `NEXT_PUBLIC_AGENT_WS_URL`
  - `__VINO_APP_URL__` → `NEXT_PUBLIC_APP_URL`
  - `__VINO_WC_PROJECT_ID__` → `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID`

### Job 3 — Deploy
- Runs a Docker daemon preflight check — fails fast with a clear fix message if the SSH user isn't in the `docker` group
- Validates that `~/vino/.env.app` and `~/vino/.env.agent` exist on the server
- Ensures `vino-net` Docker bridge network exists
- Deploys **agent first**, waits up to 2 min for `/health` to respond
- Deploys **app**, waits up to 2 min for `/health` to respond
- Prunes dangling images
- Prints running container summary

## How `NEXT_PUBLIC_*` Variables Work in Production

`NEXT_PUBLIC_*` vars are baked into the JS bundle at build time — they cannot be changed at runtime by modifying `.env.app`. The solution used:

1. **Contract addresses, RPC URLs, chain ID** — baked with real values in `Dockerfile.web` before `RUN pnpm build`
2. **Three server-specific vars** — baked as placeholder strings (`__VINO_AGENT_WS_URL__`, etc.)
3. **At container startup**, `docker-entrypoint.sh` runs `sed` to replace the three placeholders in:
   - Client chunks: `/srv/standalone/app/.next/static/chunks/*.js`
   - Server route bundles: `/srv/standalone/app/.next/server/**/*.js`
4. This means the agent WebSocket URL and app URL **can** be updated by changing `.env.app` and restarting the container — no image rebuild needed

## Manual Deployment (without CI)

```bash
# On the server — pull and run both containers
docker pull <user>/vino-agent:latest
docker pull <user>/vino-app:latest

docker network create vino-net 2>/dev/null || true
mkdir -p ~/vino/agent-data

# Agent first
docker stop vino-agent 2>/dev/null; docker rm vino-agent 2>/dev/null
docker run -d --name vino-agent --restart unless-stopped \
  --network vino-net -p 8080:8080 \
  --env-file ~/vino/.env.agent \
  -v ~/vino/agent-data:/app/agent/data \
  <user>/vino-agent:latest

# Wait for agent health
until curl -fsS http://127.0.0.1:8080/health; do sleep 3; done

# App
docker stop vino-app 2>/dev/null; docker rm vino-app 2>/dev/null
docker run -d --name vino-app --restart unless-stopped \
  --network vino-net -p 3000:3000 \
  --env-file ~/vino/.env.app \
  <user>/vino-app:latest
```

Or with docker compose (uses `~/vino/.env.app` and `~/vino/.env.agent` in the same directory):

```bash
cd ~/vino
export DOCKER_USERNAME=<your-dockerhub-user>
docker compose pull && docker compose up -d
```

## Known Issues & Fixes Applied

| Issue | Fix |
|---|---|
| `permission denied while trying to connect to the Docker daemon socket` | SSH user not in `docker` group. Run `sudo usermod -aG docker $USER` on server, log out and back in, re-run pipeline. Added preflight check to `ci.yml` that fails fast with this exact message. |
| Invoice table empty + Yield = $0 | `fetchInvoices()` in `dashboard/page.tsx` had an early return when `!isConnected`. The `/api/invoices` API route reads public on-chain data and doesn't need a wallet. Removed the guard so invoices load on page load regardless of wallet state. Yield ($35+ accrued) now populates correctly because it is computed inside `fetchInvoices`. |
| API errors silently swallowed | When `/api/invoices` returned `{success: false}`, the UI showed an empty table with no message. Fixed: `!data.success` now throws so the catch branch sets the error state with the actual error text + retry button. |
| `__VINO_APP_URL__` in server route bundles | `docker-entrypoint.sh` only replaced placeholders in static chunks. Fixed to also run `sed` on `.next/server/**/*.js` so server-side API routes get the correct URL. |
| QuickBooks `clientId='undefined'` | Trailing spaces in `.env.app` values. Docker's `--env-file` includes trailing whitespace as part of the value. Strip with `sed -i 's/[[:space:]]*$//'`. |
| Tx stuck in mempool on HTTPS | `simulateContract` + gas override created a legacy type-0 tx rejected on production HTTPS. Fixed: use `writeContractAsync` with no gas override, letting MetaMask use native EIP-1559 fee estimation. |
| `Cannot find module '/app/server.js'` | Added `outputFileTracingRoot` in `next.config.ts`; standalone output copied to `/srv/standalone/`; server starts with `node standalone/app/server.js`. |
| `$USER` unset in SSH action | GitHub Actions SSH sessions are non-login shells. Use `$HOME` instead of `/home/$USER/vino`. |
| CloudFront `/ws*` cache policy | `UseOriginCacheControlHeaders` breaks WebSocket upgrade. Must be `CachingDisabled`. |
| CloudFront `/ws*` origin missing port | Origin must point to `:8080` explicitly for the WebSocket behavior. Default port 80 routes to the wrong service. |
| Double arrow `↗ ↗` in compliance trail | Link labels like `'MockCVI.verify() ↗'` + JSX template appended another `↗`. Fixed label to `'MockCVI.verify() tx'`. |
