The Solution

vino: invoice tokenization with AI-managed yield and built-in institutional compliance.

An SME in Singapore connects their wallet, passes KYB (Cleanverse CVI), tokenizes their invoice as an ERC-721 NFT on Monad, selects USDC as their CVA settlement asset, and starts earning 3.5–7% APY while their customer's payment clears — all with a FATF Rec-16 Travel Rule report auto-generated.

Step 1 · IDENTITY Wallet connects → query_apass checks KYB status in real-time ↓ Step 2 · ONBOARD If unverified → generate_apass → MockCVI.verify() on Monad ↓ Step 3 · ASSET query_deposit_atoken_list → select USDC / USDT / EURC CVA token ↓ Step 4 · MINT Invoice NFT minted (ERC-721, keccak256 commitment) — CVI-gated ↓ Step 5 · YIELD Deposited to YieldVault → AI agent assigns Hold / Conservative / Aggressive ↓ Step 6 · PAYMENT create_payment_request → CVA-verified stablecoin settlement instructions ↓ Step 7 · AUDIT download_travel_rule → FATF Rec-16 report auto-generated from mint TX
InvoiceNFT · ERC-721
Privacy-preserving tokenization

Only keccak256(data + salt) stored on-chain. No plaintext invoice data on the public ledger — PDPA / PIPL compliant for SGP and China cross-border use.

YieldVault · Aave V3
AI-managed strategy routing

Hold (0%) · Conservative (3.5% APY) · Aggressive (7% APY). Strategy selected per-invoice by the MemoriVault agent based on risk score, market regime, and depositor's CVA eligibility.

MemoriVault Agent
Hierarchical memory + Qwen 70B

L1 working context · L2 episodic memory (RAG recall) · L3 distilled rules. Calls verify_apass every 5-minute cycle — CVA gate always active at the agent layer.

AgentRouter · On-chain
Immutable decision audit trail

Every AI strategy decision recorded on Monad via recordDecision(). 5-minute cooldown enforced. Pre-flight cooldown check avoids Monad's revert-as-OOG gas waste.

CVI · CVA Integration

Compliance is not a checkbox. It's the product moat.

Regulated Asian financial institutions cannot touch a DeFi protocol without KYB, AML, and Travel Rule support. vino is the only invoice financing protocol that integrates all three through a live Cleanverse API stack — making it the only option for bank partnerships and institutional distribution in APAC.

01
generate_apass → POST /api/cleanverse/onboard
KYB registration: customerId, wallet, chain, identityData. Returns cvRecordId displayed post-onboard as the Cleanverse proof link. Linked to MockCVI.verify() on-chain tx for dual-layer CVI proof.

02
query_apass → every page load · onboard step 2
Real-time A-Pass status check. Returns tier, expiry, status. Renders as "A-Pass · Tier N · expires MMM DD YYYY" in the CVI banner. Drives the KYB gate on mint, deposit, and settlement flows.
Plain JSON
03
MockCVI.verify(address) → Monad Testnet tx
On-chain CVI relay: the onboard API calls MockCVI.verify() via the relay wallet. txHash surfaced as clickable Monad Explorer link in the compliance audit trail. isVerified() view function gates mint and deposit at the contract level.
On-chain
04
query_deposit_atoken_list → CVA token selection
Returns USDC · USDT · EURC with issuer, kybRequired, and eligible flag. Each token rendered with a "✓ live Cleanverse" source badge. Restricted to CVA-approved stablecoins — no unverified assets enter the settlement layer.
AES-CBC
05
verify_apass → per-deposit eligibility + agent cycle gate
Cross-validates wallet × CVA token eligibility. Called on token selection UI and on every 5-minute agent analysis cycle. If A-Pass inactive: agent forces Hold strategy. Fallback: MockCVI.isVerified() on-chain. Source always shown.
AES-CBC
06
create_payment_request → CVA-verified settlement
Generates payment instructions: invoiceNft, settlement token, amount, issuerAddress. Returns send_to address, compliance_note, CVA asset. Source badge: "✓ Cleanverse API" vs "local format". Rate-limited to 20 req/hr.
AES-CBC
07
download_travel_rule → FATF Rec-16 report
Generates the FATF Recommendation 16 Travel Rule report. Mint txHash auto-populated from localStorage. Inline preview: originator, beneficiary, CVA settlement asset, compliance note. Downloadable as JSON. Critical for Singapore, Hong Kong, and Korea regulatory requirements.
